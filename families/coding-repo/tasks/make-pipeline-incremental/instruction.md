# Make pipeline builds incremental

The `pipeline` build tool in `/app` reruns every step on each `build`, which makes builds of large projects slow. Make `build` incremental: it runs a step when the paths or contents of the files its patterns match, its `run`, `inputs`, `outputs` or `params` in `pipeline.toml`, or the source of the module that defines its function have changed since the step's last successful run, when its outputs no longer hold what that run wrote, or when its last run failed, and it skips the step otherwise. An incremental build must always leave the same outputs as a build of a clean copy of the project. The records `build` keeps must never be among the files a step's patterns match.

Keep the existing `pipeline.toml` format, step interface, command line and Python API, and report skipped steps in `BuildReport.skipped`. Document how incremental builds behave in `README.md`, and add tests for them. Use only Python 3.14's standard library. Verification runs the code as an unprivileged user from a copy of `/app` that it may not be able to write, so keep the files the code or its tests create in temporary directories. It runs the tests in `/app/tests` and then its own hidden tests, and fails either run that takes more than five minutes on two CPUs.
