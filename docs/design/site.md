# Site

The site under `web/` has two views built from one Astro project and one component set: the public results, built from the committed families, systems, and reports and the nixos-config catalog, and the local vote page, which only `bench serve` hosts. [TypeScript](../conventions/typescript.md) gives the conventions for changing either, and [CI](../conventions/ci.md#deploy) covers how the public build deploys.

## Results

The site lists the families whose `family.toml` sets `public = true`, which [Authoring](../guide/authoring.md#families) defines, together with their reports, so test families stay off it. A listed family appears before its first round closes, showing its systems with unbounded intervals and its reference at 1,000. Titles and meta tags name families by their full names, and pages name systems by their display names, as [Authoring](../guide/authoring.md) defines them, which the site resolves from `family.toml`, `systems.toml`, and the nixos-config catalog. A board's URL is `/<aspect>/<slug>/`, where the slug is the family ID after its aspect prefix (`/writing/zh/`), so only a family rename moves it. The build fails when a family or report names a system without a table, and when a public family's ID does not start with its aspect.

The header links Leaderboards and Methodology at any family count, so the home page is the one index of boards. It groups the families under their aspects, each section reachable at `/#<aspect>`. A family page links its aspect's other boards by their short names behind a disclosure once the aspect lists two, a system page links the same system on those boards where it has a page, and a system page's breadcrumb leads back to its aspect and family.

Every family page opens with its scorer's steps, captioned alike on every board of one scorer and render, and links the methodology's section for that scorer and the family's cases or tasks in the repository. Each caption opens what its step means on that board, such as the family's exact gates, on tap, click, or Enter. A votes family that sets `render = "diff"`, as a coding family does, reads Run → Tests → Blind pairs → Scores, where its run names the agent and turn budget and its tests take the gates' place. Its board calls each output a solution, labels the gate-failure column Failed tests and the length bias Diff length bias, and links its tasks and the methodology's section on tests, then votes, which also defines those terms. The home panels, each family board, and the methodology's example figure sit beside a legend of the marks they draw, and below `lg`, where the leaderboard leaves out its forest plot, the board's legend moves to the Categories section. The leaderboard marks the anchor and preliminary systems with badges that open their definitions on tap, click, or Enter, as the summary's figures and the leaderboard's column headers do. On a round that cannot rank the reference, the anchor's definition names the reference it stands in for.

Each family scored by votes gets a page showing one round, with the round and category filters kept in the URL:

- **Round summary:** the [decision](ranking.md#decision), naming the leader, marked as tied with a hint on the tie-break that chose it when another ranked system ties with the top score, or saying there is none while a preliminary system is in that tie. Beside it sit the vote and session counts, the votes left out of the fit, and four of the [diagnostics](ranking.md#diagnostics): rater agreement, separated pairs, split-half τ, and the length bias. Rater agreement below the floor adds a warning.
- **Leaderboard:** a sortable table that fits its container without scrolling. Its interval column, left out below `lg`, where each interval stays as text under its score, is a forest plot on one axis shared by every row, with a rule at the anchor's score and hollow dots on dashed intervals for preliminary systems. The axis starts at most 600 points below the top score, at which the top system would take about 97% of the votes, so an interval that runs past the start ends in an arrowhead and a score past it sits there as one, with the score printed beside it in charts that have no score column. An axis labels every tick when each interval between ticks gets at least 40 px, and otherwise only its ends and the anchor's tick when it sits far enough from both. Below `md` the votes, both-bad, and gate-failure columns move into a popover that each score opens, and cost and latency stay in the section below. Choosing a category swaps in the systems that category's refit ranks, with no rank spread, and marks the columns that stay family-wide. The board's or the category's unranked systems follow the table by name, since they have no score.
- **Categories:** one forest plot per category, all on one axis that starts at the lowest of the categories' own cuts, each made below that category's own top score, so a category's wider intervals read as wider beside the others. Their rows follow the family board's order whichever category is chosen, after which come the systems only a category ranks.
- **Cost and latency:** score with its interval against the mean cost per output and against the p50 latency, with the Pareto frontier drawn as a step line and its systems labelled. Each metric uses a log axis when every value is positive and a linear axis when it includes zero. A chart with no priced or timed system is left out.

Each system has a page at `/<aspect>/<slug>/<system>/` from its latest round: its score, rank spread, and votes, then head-to-head win rates, category scores on the family page's category axis, output tokens and latency beside the other systems, the issues tagged on its outputs, each with its definition on tap, and its standing in every round it appeared in, whose date opens that round's fingerprint. Families scored by tests get a table of pass rates, and the home page shows each listed family's latest scores as a compact forest plot with its leader, followed by its unranked systems and those without votes.

Every chart has a table twin with the same values and a tooltip on hover. The static forest plots on the home page, on a family page before its first round, and in the methodology are tables themselves, with each row's score opening its interval on tap, click, or Enter. The leaderboard's interval cells repeat the Score column beside them in a hover title. Both themes read their colors from CSS variables, so a theme switch needs no re-render.

## The Vote Page

`/vote/` exists only in builds with `BENCH_LOCAL=1`, which `bench serve` makes, and it fetches pairs from the API that [Arena](arena.md#vote-api) defines at runtime. It shows the case's prompt above two outputs, or for text pairs in a column beside them from 1280 px wide, since that column would render the 1280 px preset of an HTML output at about a third of its size and leave each diff about 400 px wide. The prompt renders as Markdown, as the case author wrote it, and the checklist sits apart from it on a muted panel under What to check, since the model never saw it. The outputs scroll independently and render as written, with a toggle that renders text outputs as Markdown, while diffs show in monospace with tinted added and removed lines, and HTML outputs load in sandboxed frames from the render origin with viewport presets of 375, 768, and 1280 px. Nothing is preselected, and the verdicts, each output's issues, the note, submit, and undo each have a key, which [Voting](../guide/voting.md#casting-a-vote) lists. Each output's title band holds an Issues button, which lists the family's issues with what each means and its key, unless the family lists none. Each new pair takes focus back from the control that loaded it, so the next key is a shortcut again.

## Design Direction

The site is named HAKULA†BENCH, after the owner's blog HAKULA†CHANNEL, with the dagger as part of the name. The 95% interval is its identity: the mark beside the wordmark and in the favicon is a capped interval with its dot, the home page leads with each family's forest plot, and the empty state draws every interval unbounded. Everything else stays quiet, with ink text, one ultramarine accent, no card grid or hero number, and numbers in tabular figures. IBM Plex Sans sets all text, with Sarasa Gothic SC or Source Han Sans SC for Chinese where installed, and Maple Mono for code. Charts use one series hue and one emphasis hue, which the hovered or current system takes.
