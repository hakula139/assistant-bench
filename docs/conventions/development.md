# Development

## Dev Shell

Both Nix shells provide uv, Node.js, and pnpm. The default shell also installs the pre-commit hooks, while Python CI jobs use `.#python`:

```bash
nix develop                                 # Dev shell with uv, Node.js, and the hooks
uv sync                                     # Virtualenv with Harbor and the dev tools
pnpm install                                # Node-based formatters, linters, spell checker, and the site
nix flake check                             # Run the pre-commit hooks that need neither node_modules nor the virtualenv
```

If you use [direnv](https://direnv.net), run `direnv allow` once so `.envrc` loads the dev shell whenever you enter the repository.

Both shells export `BENCH_NIXOS_CONFIG`, described [below](#the-nixos-config-input).

The root Python project contains the `assistant_bench` CLI and the `assistant_bench_arena` voting contracts, ledger and native services. `uv sync` installs the default `bench` and `dev` dependency groups for repository commands. Pywrangler reads only the base project dependencies for the Worker runtime and maintains its PEP 751 `pylock.toml` beside the universal `uv.lock`. The primary `wrangler.toml` lives beside `pyproject.toml` so the native tools discover one project and its dependencies.

Production and staging use separate remote D1 bindings. Real votes from every device use production, while staging validates the same application.

Open `assistant-bench.code-workspace` to check the host and coding-family sources in a compatible editor, using the root `.venv`. The host project targets Python 3.14. The coding family's `pyrightconfig.json` inherits its strict diagnostics and targets Python 3.13 for standalone task scripts.

## Pre-Commit Hooks

Entering the dev shell installs a [pre-commit](https://pre-commit.com) hook generated by [`git-hooks.nix`](https://github.com/cachix/git-hooks.nix). Because the shell generates its config, `.pre-commit-config.yaml`, as a gitignored symlink in each checkout, [`AGENTS.md`](../../AGENTS.md#rules-for-every-change) asks for `nix develop -c true` in every new worktree.

The hook runs the fast subset of the [verification](../../AGENTS.md#verification) checks on staged files: file hygiene, Nix formatting and lints, Ruff, shfmt, Prettier and Taplo formatting, `markdownlint`, `cspell`, actionlint on the workflows, lychee on local links and anchors, and the sort order of `.cspell/words.txt`, while mypy and pytest stay out of the hook because they take longer.

Hooks that fix files in place fail the commit if they make changes, so stage the fixes and commit again.

Ruff, Prettier, markdownlint, and cspell skip each task's `environment/app/`, and Ruff also skips its `tests/hidden/`, since those hold the project under test in its own style.

The Node hooks run the tools pinned in `node_modules`, and the Ruff hooks run the Ruff pinned in `uv.lock`, so `pnpm install` and `uv sync` come first in a new checkout. `nix flake check` runs only the other hooks because its sandbox has neither, while [CI](ci.md#checks) runs those tools.

## Where Settings Live

Commands stay minimal, and settings live in config files:

| Setting                                                                       | Lives in                                                                                                              |
| ----------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------- |
| Ruff, mypy, pytest (including coverage and the default `-m "not docker"`), uv | `pyproject.toml`'s `[tool.*]` tables                                                                                  |
| Systems under test                                                            | `systems.toml`                                                                                                        |
| A family's scorer, systems, and samples                                       | `families/<family>/family.toml`                                                                                       |
| Model completion and context allowances                                       | The shared model catalog, or a bare route's `systems.toml` table                                                      |
| Harbor job settings, such as concurrency and retries                          | `jobs.py`, which builds each job config at run time                                                                   |
| Repeat share, seed votes, and sampling policy                                 | `src/assistant_bench_arena/scheduler.py`                                                                              |
| The voting runtime's origins, namespace, and D1 bindings                      | `wrangler.toml`                                                                                                       |
| Point-fit parameters and diagnostic coverage rules                            | `scoring/ranking.py` and `report.py`, frozen in each voted report                                                     |
| The model endpoint                                                            | The ignored `.env`                                                                                                    |
| Prettier, markdownlint, cspell, lychee, Taplo, and shfmt                      | Their own files at the repository root                                                                                |
| The site's Astro, TypeScript, ESLint, shadcn/ui, and Vitest settings          | `web/astro.config.ts`, `web/tsconfig.json`, `web/eslint.config.js`, `web/components.json`, and `web/vitest.config.ts` |
| The Cloudflare Workers deploy                                                 | `web/wrangler.toml`                                                                                                   |
| Codecov's project and patch status targets, per flag                          | `codecov.yml`                                                                                                         |

Environment variables carry secrets and per-environment values: the `BENCH_API_*` endpoint settings from `.env`, the Nix store path `BENCH_NIXOS_CONFIG` from the dev shell, and an optional `BENCH_DATA_DIR` that moves the [data directory](data.md#the-data-directory). Runtime origins and D1 bindings belong to the named staging and production targets in `wrangler.toml`. [Arena](../design/arena.md) defines their admission and administration boundaries.

`bench` sets `HARBOR_TELEMETRY=off` and `LITELLM_MODE=PRODUCTION` in its own environment, which Harbor inherits, because Harbor reads telemetry consent and LiteLLM its `.env` switch from nowhere else.

Job configs are generated per run and never committed. Harbor copies each one into its job directory as `config.json`.

## Toolchain and Pins

- The flake pins the stable Nixpkgs channel for Node.js and the hooks, and takes uv from Nixpkgs master to meet the Python Worker tooling's minimum version. uv installs the CPython that `.python-version` names from its python-build-standalone builds, and `python-preference = "only-managed"` in `[tool.uv]` keeps it from using any other Python on `PATH`. A host's first install takes the newest patch release the pinned uv knows, while an existing install stays on its patch until `uv python upgrade`.
- On NixOS, that interpreter and the Ruff binary from its wheel are generic Linux executables, so they run through `programs.nix-ld`, which also provides the C++ runtime and zlib that Linux wheels link.
- Renovate follows the shared preset, which automerges lock file maintenance, including the flake lock update that moves the nixos-config input. The [fingerprint check](ci.md#checks) fails such a PR when the bump changes a system's fingerprint.
- `uv.lock` pins the Python dependencies, including Ruff, mypy and basedpyright, and `pnpm-lock.yaml` pins the Node tools, with Dependabot opening security updates for both.

## The nixos-config Input

The flake reads the model catalog and the rendered assistant instructions from [nixos-config](https://github.com/hakula139/nixos-config), as [Systems](../design/systems.md#the-nixos-config-export) describes:

```bash
nix build .#nixos-config                    # Build the export on its own
nix flake update nixos-config               # Move to the latest nixos-config commit
```

A bump that changes a system's resolved prompt, route, or effort changes its fingerprint, which [Systems](../design/systems.md#fingerprints) covers, and [Authoring](../guide/authoring.md#systems) gives the recipe for keeping the old name on its old resolution.

## Nix Style

`nixfmt` formats `flake.nix`, and `statix` and `deadnix` lint it. These rules cover what the tools leave open:

- Keep code and comments within 100 columns, counting the indent. Because `nixfmt` does not reflow comments, wrap them by hand.
- Mark the file header with `=` banners at column 0, and mark each section with `-` banners indented to match the surrounding code. Every banner line ends at column 100.

## Config Style

Because Prettier and Taplo leave long strings alone and shfmt does not wrap, wrap YAML, TOML, and shell files by hand. Keep comments within 100 columns and other lines within about 100, counting the indent, unless a line holds an unbreakable token such as a URL.
