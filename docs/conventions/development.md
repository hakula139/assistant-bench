# Development

Learn how to set up the development environment, what the pre-commit hooks check, where each setting lives, how the toolchain and the nixos-config input are pinned, how Nix and config files are styled, and what CI runs.

## Dev Shell

The Nix flake provides two shells: the default shell holds Python 3.14, uv, Node.js, pnpm, and the pre-commit hooks, while `.#python` holds only Python and uv, which the Python CI jobs use:

```bash
nix develop                                 # Dev shell with Python, uv, Node.js, and the hooks
uv sync                                     # Virtualenv with Harbor and the dev tools
pnpm install                                # Node-based formatters, linters, and spell checker
nix flake check                             # Run the pre-commit hooks that need neither node_modules nor the virtualenv
```

If you use [direnv](https://direnv.net), run `direnv allow` once so `.envrc` loads the dev shell whenever you enter the repository.

Both shells set `UV_PYTHON` to the flake's Python and export `BENCH_NIXOS_CONFIG`, described [below](#the-nixos-config-input).

## Pre-Commit Hooks

Entering the dev shell installs a [pre-commit](https://pre-commit.com) hook generated by [`git-hooks.nix`](https://github.com/cachix/git-hooks.nix). Because the shell generates its config, `.pre-commit-config.yaml`, as a gitignored symlink in each checkout, [`AGENTS.md`](../../AGENTS.md#rules-for-every-change) asks for `nix develop -c true` in every new worktree.

The hook runs the fast subset of the [verification](../../AGENTS.md#verification) checks on staged files: file hygiene, Nix formatting and lints, Ruff, shfmt, Prettier and Taplo formatting, `markdownlint`, and `cspell`, while mypy and pytest stay out of the hook because they take longer. Hooks that fix files in place fail the commit if they make changes, so stage the fixes and commit again.

Run `pnpm install` and `uv sync` in each new checkout because the Node hooks run the tools pinned in `node_modules` and the Ruff hooks run the Ruff pinned in `uv.lock`. `nix flake check` runs only the other hooks because its sandbox has neither, while CI's Node Check and Python Check jobs run those tools.

## Where Settings Live

Commands stay minimal, and settings live in config files:

| Setting                                                                       | Lives in                                            |
| ----------------------------------------------------------------------------- | --------------------------------------------------- |
| Ruff, mypy, pytest (including coverage and the default `-m "not docker"`), uv | `pyproject.toml`'s `[tool.*]` tables                |
| Systems under test                                                            | `systems.toml`                                      |
| A family's scorer, systems, samples, and output bound                         | `families/<family>/family.toml`                     |
| Harbor job settings, such as concurrency and retries                          | `jobs.py`, which builds each job config at run time |
| The model endpoint                                                            | The ignored `.env`                                  |
| Prettier, markdownlint, cspell, Taplo, and shfmt                              | Their own files at the repository root              |

Environment variables carry only secrets and per-environment values: the `BENCH_API_*` endpoint settings from `.env`, and the Nix store paths `BENCH_NIXOS_CONFIG` and `UV_PYTHON` from the dev shell. The bench sets `HARBOR_TELEMETRY=off` for each Harbor run because Harbor reads that setting from nowhere else. Job configs are generated per run and never committed, and Harbor copies each one into its job directory as `config.json`.

## Toolchain and Pins

- The flake pins Nixpkgs, which supplies Python, uv, and Node.js. Both shells set `UV_PYTHON` to that Python, and `[tool.uv]` never downloads another.
- Renovate follows the shared preset, which automerges lock file maintenance, including the flake lock update that moves the nixos-config input. The [fingerprint check](#ci) fails such a PR when the bump changes a system's fingerprint.
- `uv.lock` pins Harbor, Ruff, mypy, and pytest, and `pnpm-lock.yaml` pins the Node tools, with Dependabot opening security updates for both.
- `pyproject.toml` names PyPI as the default index and `.npmrc` names the npm registry, so both lockfiles resolve from public registries whatever the local package manager config says. A test fails if either lockfile names another host.

## The nixos-config Input

The flake reads the model catalog and the rendered assistant instructions from [nixos-config](https://github.com/hakula139/nixos-config), as [Systems](../design/systems.md#the-nixos-config-export) describes:

```bash
nix build .#nixos-config                    # Build the export on its own
nix flake update nixos-config               # Move to the latest nixos-config commit
```

A bump that changes a system's resolved prompt, route, or effort changes its fingerprint, and the fingerprint check fails until the changed system takes a new name in `systems.toml`.

## Nix Style

`nixfmt` formats `flake.nix`, and `statix` and `deadnix` lint it. These rules cover what the tools leave open:

- Keep code and comments within 100 columns, counting the indent. Because `nixfmt` does not reflow comments, wrap them by hand.
- Mark the file header with `=` banners at column 0, and mark each section with `-` banners indented to match the surrounding code. Every banner line ends at column 100.

## Config Style

Because Prettier and Taplo leave long strings alone and shfmt does not wrap, wrap YAML, TOML, and shell files by hand. Keep comments within 100 columns and other lines within about 100, counting the indent, unless a line holds an unbreakable token such as a URL. The flake leaves every shfmt setting null because passing any formatting flag makes shfmt ignore `.editorconfig`, where it reads its layout.

## CI

CI runs on pushes to `main`, pull requests, and manual dispatch:

| Job             | Checks                                                                                                                                    |
| --------------- | ----------------------------------------------------------------------------------------------------------------------------------------- |
| Nix Flake Check | `nix flake check`, which runs the pre-commit hooks without the Node and Ruff ones                                                         |
| Node Check      | `pnpm format`, `pnpm lint`, and `pnpm spellcheck`                                                                                         |
| Python Check    | `uv sync --locked`, `ruff check`, `ruff format --check`, mypy, pytest with coverage uploaded to Codecov, and on PRs the fingerprint check |
| Harbor Smoke    | `uv run bench check smoke` and `uv run pytest -m docker` under Docker                                                                     |
| CI Result       | Fails when any job above fails or is cancelled, so branch protection can require this job alone                                           |

The fingerprint check runs `uv run bench fingerprints <base>` against the PR's base commit. It resolves every `systems.toml` table at both commits, each against its own nixos-config export, and fails when a table keeps its name but its fingerprint changes, so a changed system takes a new name and the old one keeps its results.

No job sends a paid request, and no job reads any secret other than the Cachix and Codecov tokens. List each new job in CI Result's `needs`.

Write multiline step text as one heredoc, never as repeated `printf` or `echo >>` calls. When the text includes a command's output, read the output into a variable first, since a failed command substitution inside a heredoc does not fail the step under `bash -e`.
